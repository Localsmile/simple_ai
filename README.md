# Simple AI

GitHub Pages에서 실행되는 OpenAI 호환 API용 로컬 우선 채팅 클라이언트입니다. 별도 백엔드 없이 브라우저가 공급자 API와 직접 통신합니다.

## 핵심 기능

- 모든 OpenAI 호환 `/chat/completions` 엔드포인트를 커스텀 연결로 등록
- 엔드포인트와 API 키를 재사용하는 다중 연결 프리셋 및 입력창 빠른 전환
- 대화별 연결 프리셋·모델·Vision·시스템 프롬프트·생성 설정 유지
- 새 대화의 시스템 프롬프트는 빈값으로 시작
- 클릭·드래그앤드롭·클립보드 붙여넣기로 이미지와 텍스트·Markdown·CSV·JSON·코드 파일 첨부
- 모델별 수동 Vision 활성화
- 시스템 프롬프트, temperature, 최대 출력 토큰, 스트리밍 설정
- 대화별 추론 레벨·토큰 예산·사용자 정의 요청 매핑 및 프리셋별 기본값
- 대화별 컨텍스트 토큰 한도와 전송할 최근 대화 턴 수 지정(화면 기록은 유지)
- GFM Markdown, 코드 하이라이트·복사, 표, 링크, 본문 내 이미지
- IndexedDB 기반 최근 대화 30개 저장 및 수동 변경 제목 유지
- 사용자 메시지와 응답의 수정·개별 삭제·답변 후보 재생성·새 대화로 분기
- API 응답에 포함된 입력·출력·캐시 토큰 표시
- 응답 대기 단계와 경과 시간 표시, 전송 메시지 즉시 저장
- 여러 원격 Streamable HTTP MCP 서버 연결 및 전송할 도구 선택(Beta)
- API가 제공하는 추론 과정(`reasoning`, `reasoning_content`) 접기/펼치기
- 스트리밍 중 사용자의 스크롤 위치를 존중하는 하단 자동 추적
- 답변과 재생성 후보별 생성 모델·연결 프리셋 표시
- 모바일 안전 영역, 터치 조작과 가상 키보드 대응
- 모바일 Enter 줄바꿈, PC Enter 전송 및 공용 전송 단축키 설정
- 대화별 마크다운 시작 메시지와 사용자 메시지 마크다운 렌더링
- 모든 대화에 공통 적용되는 마크다운 이미지 크기 설정
- 본문 없이 thinking만 반환한 응답의 상태 표시와 수동 본문 사용
- 모바일 레이아웃과 다크·라이트 테마

## 로컬 실행

Node.js 22.13 이상이 필요합니다.

```powershell
npm install
npm run dev
```

브라우저에서 `http://localhost:5173`을 엽니다.

정적 결과물 검증:

```powershell
npm test
npx serve dist
```

## GitHub Pages

`main` 브랜치에 push하면 [`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml)이 `dist`를 배포합니다. 저장소의 **Settings → Pages → Source**는 **GitHub Actions**로 설정합니다.

프로젝트 페이지(`username.github.io/repository`)에서는 빌드 시 저장소 이름이 asset path로 자동 적용됩니다. 사용자·조직 페이지(`username.github.io`)에서는 루트 경로를 사용합니다. 사용자 지정 도메인의 루트에 배포할 때는 Actions 빌드 환경에 `PAGES_BASE_PATH`를 빈 값으로 지정할 수 있습니다.

## 데이터 및 보안

- 대화와 첨부 파일은 현재 브라우저의 IndexedDB에 저장됩니다.
- 대화 설정에는 연결 프리셋 ID와 모델·생성값만 저장되며 API 키는 복제되지 않습니다.
- 각 연결 프리셋의 API 키와 MCP 토큰은 기본적으로 `localStorage`에 보관됩니다.
- `인증정보 로컬 저장`을 끄면 인증정보는 현재 탭 세션의 `sessionStorage`에만 남습니다.
- 정적 BYOK 앱 특성상 인증정보는 브라우저 개발자 도구에서 확인 가능합니다. 공용 기기에는 키를 저장하지 않는 구성이 적합합니다.
- 공급자가 브라우저 직접 호출을 허용하지 않으면 CORS 오류가 발생합니다. 이 경우 CORS 허용 프록시나 별도 백엔드가 필요합니다.
- GitHub Pages는 HTTPS이므로 원격 API와 MCP도 HTTPS가 필요합니다. `localhost` 테스트만 HTTP를 사용합니다.

## 파일과 Vision 호환 범위

이미지는 OpenAI Chat Completions의 `image_url` content part로 전송됩니다. 해당 형식을 지원하는 vision 모델에서만 동작합니다. 텍스트 계열 파일은 브라우저에서 읽어 사용자 메시지의 파일 컨텍스트로 포함됩니다. PDF, DOCX 및 기타 바이너리 문서는 공급자 간 표준 형식이 없어 현재 버전에서 제외합니다.

## 메시지 편집 동작

수정과 삭제는 선택한 메시지 한 개에만 적용됩니다. 최신 답변의 `다시 생성`은 기존 답변을 삭제하지 않고 새 후보를 추가하며, 좌우 화살표로 사용할 답변을 선택할 수 있습니다. 상단 누적 토큰은 저장된 모든 답변 후보의 사용량을 포함합니다.

후속 대화가 이미 있는 과거 답변을 재생성하거나 다른 후보로 바꾸면 원본 흐름을 유지한 채 해당 지점에서 새 대화로 자동 분기됩니다.

`분기`는 선택한 메시지까지의 기록과 해당 대화의 연결·모델·시스템 프롬프트·생성 설정을 새 대화로 복사합니다. 원본 대화는 변경되지 않습니다. 최근 대화 목록의 연필 버튼으로 저장된 제목을 변경할 수 있습니다.

## 추론 설정과 입력 동작

설정의 연결 탭에서 프리셋별 추론 전송 형식·사용할 레벨 목록·기본 레벨을 지정합니다. `reasoning_effort`, `reasoning` 객체(레벨 또는 토큰 예산), `thinking` + `reasoning_effort`, 사용자 정의 레벨별 JSON 매핑을 지원합니다. 토큰 예산과 사용자 정의 매핑도 프리셋에 저장됩니다.

입력창의 모델 선택 옆 `추론` 선택에는 해당 프리셋에서 선택한 레벨만 표시됩니다. 여기서 바꾼 값은 현재 대화에만 저장되며 프리셋 기본값은 변경하지 않습니다. 새 대화나 프리셋 전환 시에는 연결 탭에서 지정한 기본 레벨을 적용합니다. 기존 대화를 열면 저장된 레벨을 복원하고, 그 레벨이 프리셋 목록에서 제거됐다면 프리셋 기본값을 적용합니다. 전송 형식·매핑·예산은 연결 탭의 현재 프리셋 설정을 따릅니다.

`API 기본값`은 별도 추론 옵션을 추가하지 않습니다. 레벨 목록은 여러 API의 요청 값 모음이며 모델의 지원 목록을 자동 조회한 결과가 아닙니다. `max`도 공통 토큰 수나 모든 모델의 최고 단계를 의미하지 않습니다. API·모델마다 지원 형식과 레벨이 다르므로 추론 미지원 모델을 강제로 활성화할 수는 없습니다. 명시적으로 선택한 추론 설정은 추가 요청 JSON의 같은 항목보다 우선하며, API 기본값에서는 추가 요청 JSON을 그대로 적용합니다. `reasoning` 객체는 레벨과 토큰 예산 중 하나만 전송합니다. 토큰 예산과 최대 출력 토큰의 제약도 공급자 문서를 확인해야 합니다.

다른 규격은 사용자 정의 매핑에 선택할 레벨을 키로, 실제 전송할 객체를 값으로 지정합니다. 예를 들어 `{"budget":{"custom_parameter":"$budget"}}`에서 `"$budget"`은 입력한 숫자로, `"$level"`은 선택한 레벨 문자열로 치환됩니다. `null` 값은 해당 요청 필드를 제거합니다. 모델·메시지·도구 등 앱이 관리하는 필드는 덮어쓸 수 없습니다. 이 매핑에는 인증정보를 넣지 않습니다.

MCP 도구 결과를 이어 보낼 때 응답의 `reasoning`, `reasoning_content`, `reasoning_details`를 보존합니다. 공개 텍스트·요약만 thinking에 표시하며 암호화 데이터는 표시하지 않습니다. 호환 규격 참고: [OpenRouter 추론 문서](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).

전송 단축키 기본값은 자동입니다. 주 입력 장치가 터치인 기기에서는 Enter가 줄바꿈이며 전송 버튼으로 보냅니다. PC에서는 Enter 전송, Shift+Enter 줄바꿈입니다. 공용 설정에서 Enter 줄바꿈 + Ctrl/⌘+Enter 전송으로 변경할 수 있습니다. 한글 등 IME 조합 확정 Enter는 전송하지 않습니다.

## 컨텍스트 관리

`전송할 최근 대화 턴`은 API에 포함할 사용자·응답 묶음의 수를 직접 지정합니다. 기본값은 최근 20턴이며 `-1`은 전체 대화입니다. 그다음 토큰 자동 정리를 켜면 설정한 모델 한도에서 최대 출력 토큰과 안전 여유분을 확보한 뒤 필요한 경우 더 오래된 턴을 제외합니다. 제외된 대화는 화면과 IndexedDB 기록에 그대로 남으며 응답 상단에 제외된 메시지 수가 표시됩니다. 토큰 수는 공급자별 토크나이저 차이 때문에 보수적인 추정치입니다.

상단의 `TOTAL · IN · OUT · CACHE`는 마지막 요청이 아니라 현재 대화에 저장된 모든 응답의 누적 사용량입니다. 413은 모델의 컨텍스트 토큰 한도가 아닌 API 서버 또는 게이트웨이의 HTTP 요청 본문 크기 제한입니다. 최신 메시지나 첨부 파일 하나만으로 이 제한을 넘으면 자동 정리로 해결할 수 없습니다.

413 응답에 따른 자동 재시도는 하지 않습니다. 대화별 최근 턴 수를 줄여 요청 범위를 명시적으로 조절할 수 있습니다.

메시지를 전송하면 사용자 입력과 첨부 파일의 저장을 즉시 시작하되 API 요청을 기다리게 하지 않습니다. 생성 도중 새로고침해도 사용자 메시지는 남고, 아직 받지 못한 응답 자리만 복원되지 않습니다.

## MCP 범위

MCP 지원은 브라우저에서 직접 접근 가능한 원격 **Streamable HTTP** 서버의 도구 목록과 도구 호출만 포함합니다. 서버는 HTTPS, POST 요청, CORS, 필요한 MCP 헤더 노출을 지원해야 합니다. 로컬 stdio MCP 서버, OAuth 로그인, resources, prompts, 서버 알림 스트림은 포함하지 않습니다.

처음 실행할 때 MCP는 켜져 있으며 Exa의 `web_search_exa`만 선택됩니다. GitHub와 다른 도구는 기본 활성화하지 않습니다. 기존에 저장된 서버·도구 선택·MCP OFF 설정은 유지하며, 삭제한 서버를 자동 복구하지 않습니다. 기본 웹검색은 별도 API 키 없이 연결되지만 서비스 자체의 사용량·속도 제한은 적용됩니다. [Exa MCP 문서](https://exa.ai/docs/reference/exa-mcp).

서버를 여러 개 등록하고 서버마다 URL·인증정보·활성 여부를 따로 저장합니다. `연결`로 목록을 불러온 뒤 필요한 도구만 선택합니다. 직접 추가한 새 서버는 도구가 선택되지 않은 상태이며, Exa 프리셋만 웹검색 도구를 미리 선택합니다. 기존 단일 서버 설정과 토큰은 자동 이전됩니다. 프리셋 버튼은 `추가됨`과 실제 `연결됨`·`연결 중`·`연결 오류`를 구분합니다. 이미 추가된 프리셋 버튼을 누르면 해당 서버 설정으로 이동하며 중복 추가하지 않습니다.

모델에는 활성 서버에서 선택한 도구의 스키마만 전달됩니다. 같은 이름의 도구도 서버별로 구분하여 호출합니다. 앱에서 서버·전송 도구 개수에 별도 제한을 두지 않으며, 이전 24개 제한 설정은 제거됩니다. 실제 API의 도구 수·요청 크기·컨텍스트 한도는 그대로 적용됩니다. 모든 도구를 해제하면 MCP 호출 없이 일반 채팅으로 동작합니다. 선택한 도구 소실·선택한 서버 연결 실패 시 일부 도구를 임의로 빼지 않고 오류를 표시합니다. 의미 기반 자동 도구 추천이나 자동 서버 라우팅은 하지 않습니다.

도구 목록의 페이지를 모두 조회하고, 연결과 목록은 페이지를 새로고침하기 전까지 재사용합니다. URL·인증정보 변경 또는 수동 새로고침 시 다시 연결합니다. 서버 연결은 최대 3개씩 병렬 처리하고 실제 도구 실행은 모델이 반환한 순서대로 진행합니다. 생성 요청은 최대 5라운드이며, 개별 연결 요청은 20초·도구 호출은 60초 제한을 둡니다.

MCP 설정에는 Exa 웹 검색과 GitHub 읽기 전용 프리셋이 포함됩니다. GitHub 프리셋은 `https://api.githubcopilot.com/mcp/readonly`와 Bearer 인증을 적용하며, 저장소 접근 권한을 최소화한 GitHub PAT가 필요합니다. 설정 화면의 파란색 인증 토큰 발급 링크에서 fine-grained PAT 생성 화면을 열 수 있습니다. 프리셋 추가는 다른 서버의 URL·토큰을 변경하지 않습니다.
