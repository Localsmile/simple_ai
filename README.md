# Simple AI

GitHub Pages에서 실행되는 OpenAI 호환 API용 로컬 우선 채팅 클라이언트입니다. 별도 백엔드 없이 브라우저가 공급자 API와 직접 통신합니다.

## 핵심 기능

- 모든 OpenAI 호환 `/chat/completions` 엔드포인트를 커스텀 연결로 등록
- 엔드포인트와 API 키를 재사용하는 다중 연결 프리셋 및 입력창 빠른 전환
- 대화별 연결 프리셋·모델·Vision·시스템 프롬프트·생성 설정 유지
- 새 대화의 시스템 프롬프트는 빈값으로 시작
- 클릭·드래그앤드롭·클립보드 붙여넣기로 이미지와 텍스트·Markdown·CSV·JSON·코드 파일 첨부
- 모델별 수동 Vision 활성화
- 시스템 프롬프트, temperature, 최대 출력 토큰, 스트리밍 설정
- 대화별 컨텍스트 토큰 한도와 전송할 최근 대화 턴 수 지정(화면 기록은 유지)
- GFM Markdown, 코드 하이라이트·복사, 표, 링크, 본문 내 이미지 및 개별 크기 조절
- IndexedDB 기반 최근 대화 30개 저장 및 수동 변경 제목 유지
- 사용자 메시지와 응답의 수정·개별 삭제·답변 후보 재생성·새 대화로 분기
- API 응답에 포함된 입력·출력·캐시 토큰 표시
- 응답 대기 단계와 경과 시간 표시, 전송 메시지 즉시 저장
- 원격 Streamable HTTP MCP 도구 호출(Beta)
- API가 제공하는 추론 과정(`reasoning`, `reasoning_content`) 접기/펼치기
- 스트리밍 중 사용자의 스크롤 위치를 존중하는 하단 자동 추적
- 답변과 재생성 후보별 생성 모델·연결 프리셋 표시
- 모바일 안전 영역, 터치 조작과 가상 키보드 대응
- 모바일 레이아웃과 다크·라이트 테마

## 로컬 실행

Node.js 22.13 이상이 필요합니다.

```powershell
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다.

정적 결과물 검증:

```powershell
npm test
npx serve dist
```

## GitHub Pages

`main` 브랜치에 push하면 [`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml)이 `dist`를 배포합니다. 저장소의 **Settings → Pages → Source**는 **GitHub Actions**로 설정합니다.

프로젝트 페이지(`username.github.io/repository`)에서는 빌드 시 저장소 이름이 asset path로 자동 적용됩니다. 사용자·조직 페이지(`username.github.io`)에서는 루트 경로를 사용합니다. 사용자 지정 도메인의 루트에 배포할 때는 Actions 빌드 환경에 `PAGES_BASE_PATH`를 빈 값으로 지정할 수 있습니다.

## 데이터 및 보안

- 대화와 첨부 파일은 현재 브라우저의 IndexedDB에 저장됩니다.
- 대화 설정에는 연결 프리셋 ID와 모델·생성값만 저장되며 API 키는 복제되지 않습니다.
- 각 연결 프리셋의 API 키와 MCP 토큰은 기본적으로 `localStorage`에 보관됩니다.
- `인증정보 로컬 저장`을 끄면 인증정보는 현재 탭 세션의 `sessionStorage`에만 남습니다.
- 정적 BYOK 앱 특성상 인증정보는 브라우저 개발자 도구에서 확인 가능합니다. 공용 기기에는 키를 저장하지 않는 구성이 적합합니다.
- 공급자가 브라우저 직접 호출을 허용하지 않으면 CORS 오류가 발생합니다. 이 경우 CORS 허용 프록시나 별도 백엔드가 필요합니다.
- GitHub Pages는 HTTPS이므로 원격 API와 MCP도 HTTPS가 필요합니다. `localhost` 테스트만 HTTP를 사용합니다.

## 파일과 Vision 호환 범위

이미지는 OpenAI Chat Completions의 `image_url` content part로 전송됩니다. 해당 형식을 지원하는 vision 모델에서만 동작합니다. 텍스트 계열 파일은 브라우저에서 읽어 사용자 메시지의 파일 컨텍스트로 포함됩니다. PDF, DOCX 및 기타 바이너리 문서는 공급자 간 표준 형식이 없어 현재 버전에서 제외합니다.

## 메시지 편집 동작

수정과 삭제는 선택한 메시지 한 개에만 적용됩니다. 최신 답변의 `다시 생성`은 기존 답변을 삭제하지 않고 새 후보를 추가하며, 좌우 화살표로 사용할 답변을 선택할 수 있습니다. 상단 누적 토큰은 저장된 모든 답변 후보의 사용량을 포함합니다.

후속 대화가 이미 있는 과거 답변을 재생성하거나 다른 후보로 바꾸면 원본 흐름을 유지한 채 해당 지점에서 새 대화로 자동 분기됩니다.

`분기`는 선택한 메시지까지의 기록과 해당 대화의 연결·모델·시스템 프롬프트·생성 설정을 새 대화로 복사합니다. 원본 대화는 변경되지 않습니다. 최근 대화 목록의 연필 버튼으로 저장된 제목을 변경할 수 있습니다.

## 컨텍스트 관리

`전송할 최근 대화 턴`은 API에 포함할 사용자·응답 묶음의 수를 직접 지정합니다. 기본값은 최근 20턴이며 `-1`은 전체 대화입니다. 그다음 토큰 자동 정리를 켜면 설정한 모델 한도에서 최대 출력 토큰과 안전 여유분을 확보한 뒤 필요한 경우 더 오래된 턴을 제외합니다. 제외된 대화는 화면과 IndexedDB 기록에 그대로 남으며 응답 상단에 제외된 메시지 수가 표시됩니다. 토큰 수는 공급자별 토크나이저 차이 때문에 보수적인 추정치입니다.

상단의 `TOTAL · IN · OUT · CACHE`는 마지막 요청이 아니라 현재 대화에 저장된 모든 응답의 누적 사용량입니다. 413은 모델의 컨텍스트 토큰 한도가 아닌 API 서버 또는 게이트웨이의 HTTP 요청 본문 크기 제한입니다. 최신 메시지나 첨부 파일 하나만으로 이 제한을 넘으면 자동 정리로 해결할 수 없습니다.

413 응답에 따른 자동 재시도는 하지 않습니다. 대화별 최근 턴 수를 줄여 요청 범위를 명시적으로 조절할 수 있습니다.

메시지를 전송하면 사용자 입력과 첨부 파일의 저장을 즉시 시작하되 API 요청을 기다리게 하지 않습니다. 생성 도중 새로고침해도 사용자 메시지는 남고, 아직 받지 못한 응답 자리만 복원되지 않습니다.

## MCP 범위

MCP 지원은 브라우저에서 직접 접근 가능한 원격 **Streamable HTTP** 서버의 도구 목록과 도구 호출만 포함합니다. 서버는 HTTPS, POST 요청, CORS, 필요한 MCP 헤더 노출을 지원해야 합니다. 로컬 stdio MCP 서버, OAuth 로그인, resources, prompts, 서버 알림 스트림은 포함하지 않습니다.

MCP 설정에는 Exa 웹 검색과 GitHub 읽기 전용 프리셋이 포함됩니다. GitHub 프리셋은 `https://api.githubcopilot.com/mcp/readonly`와 Bearer 인증을 적용하며, 저장소 접근 권한을 최소화한 GitHub PAT가 필요합니다. 설정 화면의 인증 토큰 발급 링크에서 fine-grained PAT 생성 화면을 열 수 있습니다. 프리셋 전환 시 이전 서버의 토큰은 자동으로 비워집니다.
